# ADR-001: 采用 FastAPI 作为 API 层

- **状态**：Accepted（2026-09-24）
- **背景**：需要一个轻量、类型友好、与 Python 生态契合的 HTTP 框架暴露 AI 能力。
- **决策**：采用 FastAPI 作为 API 层，且**路由层仅做装配**，所有业务逻辑委托给 `agent` / `retriever` / `tools`。
- **后果**：
  - 正向：自动生成 OpenAPI 文档、pydantic 校验、异步友好。
  - 负向：需固定 FastAPI/pydantic 版本避免 API 漂移；路由函数不标注返回类型以规避联合类型响应模型坑。

# ADR-002: 离线优先的 Mock 提供方

- **状态**：Accepted（2026-09-24）
- **背景**：要求「干净环境一键复现」「无网络/无Key/无权重下全绿」，否则无法保证可交付。
- **决策**：为 LLM / 嵌入 / 向量库各提供零依赖 Mock 实现，作为默认后端；生产实现通过环境变量切换。
- **后果**：
  - 正向：测试、CI、E2E 全部离线可跑；复现成本低。
  - 负向：Mock 回答为确定性拼装，不代表真实模型质量；生产需安装 `requirements-ai.txt`。

# ADR-003: 混合检索 + 恒非负 BM25 idf

- **状态**：Accepted（2026-09-24）
- **背景**：纯向量检索对关键词敏感查询易漏召；现成 `rank_bm25` 在极小语料下 idf 可为负导致排序反转。
- **决策**：向量检索与 BM25 关键词检索并行，用倒数排名融合（RRF）合并；BM25 idf 采用 `ln(1 + (N-n+0.5)/(n+0.5))` 保证恒非负。
- **后果**：
  - 正向：检索召回稳定，小语料下排序正确。
  - 负向：BM25 自实现需维护，但代码量极小且可控。
